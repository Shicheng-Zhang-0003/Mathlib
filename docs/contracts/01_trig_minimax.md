## 1. The Mathematical Identity
*What fundamental mathematical truth or definition does this module enforce?*
- **Core Equation — sin/cos Taylor in even/odd Horner form:** active kernels in `src/internal/minimax.h` are NOT Remez minimax. `taylor_sin_coeffs` holds 10 coefficients for sin(x) = x*P(x*x) degree 19 in x (degree 9 in t=x*x), `taylor_cos_coeffs` holds 10 coefficients for cos(x) = P(x*x) degree 18 in x (degree 9 in t=x*x), with 1/k! entries e.g. -0.16666666666666666, 0.008333333333333333, -0.5, 0.041666666666666664. Evaluation is compensated double-double Horner via `ml_ddx_from_d`, `ml_ddx_mul_d`, `ml_ddx_add_d`, `ml_ddx_to_d` from `src/internal/error_free.h`, then `x*P` for sin. True Remez sets live DORMANT in `src/internal/minimax_coeffs.h` (`minimax_sin_coeffs`, `minimax_cos_coeffs`, `minimax_exp_coeffs`, `minimax_log_coeffs`, header `MATHLIB_V12A1_MINIMAX_TRUTH_V3`, no code includes it yet).
- **Algebraic Invariants:** sin-squared plus cos-squared equals 1, enforced by shared reduction plus quadrant swap; `ml_sin`/`ml_cos` in `src/trig.c` derive from the same reduced `y` so the identity holds to rounding. `ml_sinpi`/`ml_cospi` enforce period-2 exactness: `ml_fmod(x, 2.0)` then fold to -1..1, with exact returns for r 0.0, plus/minus 1.0 giving signed zero, plus/minus 0.5 giving plus/minus 1.0 or 0.0. `ml_sinc` enforces limit 1.0 at 0.0 with series `1.0 - x*x/6.0` for `ml_fabs(x) < 1.5e-8`.
- **atan identity and reduction to tan(pi/12):** `ml_atan` in `src/trig.c:159` reduces any finite x to core interval magnitude <= tan(pi/12) = 0.2679491924311227 via identities atan(x) = pi/2 - atan(1/x) for magnitude > 1, atan(x) = pi/4 + atan((x-1)/(x+1)) for x > 0.5, atan(x) = pi/12 + atan((x-t)/(1+t*x)) for x > tan(pi/12), symmetric negatives. Core `ml_atan_raw_dd` in `src/trig.c:148` evaluates atan(x) = x*P(x*x) with P = sum (-1)^k t^k/(2k+1), 22 terms through x^43, double-double Horner seeded from 1.0/43.0 down k=20..0. Reconstruction adds back pi/2, pi/4, pi/12 slices in double-double via `ml_two_sum` plus `ml_ddx_renorm` and `ml_ddx_to_d`.
- **asin/acos half-angle via atan:** `ml_asin` in `src/trig.c:225` returns NaN outside -1..1, plus/minus pi/2 at plus/minus 1.0, `pi/2 - 2*ml_atan(ml_sqrt((1-x)/(1+x)))` for x > 0.9, mirrored negative branch for x < -0.9, else `2*ml_atan(x/(1+ml_sqrt(1-x*x)))`. `ml_acos` in `src/trig.c:234` returns NaN outside -1..1, `2*ml_atan(ml_sqrt((1-x)/(1+x)))` for x >= 0, else `ML_PI - 2*ml_atan(ml_sqrt((1+x)/(1-x)))`. `ml_acot` in `src/trig.c:240` uses `ml_atan(1/x)` for x > 1, `ML_PI + ml_atan(1/x)` for x < -1 to avoid cancellation in pi/2-atan(x), else pi/2-atan(x).
- **atan2 Annex-F tree:** `ml_atan2` in `src/trig.c:300` implements strict IEEE-754 Annex F: NaN if either arg NaN; signed-zero matrix via `ml_signbit` for y-zero/x-zero combos (plus 0/minus 0 with minus 0 gives plus/minus pi, plus 0 with minus 0 gives pi per fixed comment); x-zero gives plus/minus pi/2 by y sign; y-zero with negative x gives plus/minus pi else signed zero; inf/inf gives plus/minus pi/4 and plus/minus 3pi/4 quadrants; inf x gives copysigned pi or 0; inf y gives plus/minus pi/2; finite path is `ml_atan(y/x)` plus/minus pi when x negative.
- **sinpi/cospi exact reduction:** `ml_sinpi` in `src/trig.c:104` and `ml_cospi` in `src/trig.c:127` reduce with exact `ml_fmod(x, 2.0)` (handles large magnitude via fmod, no Cody-Waite needed), fold r to -1..1, short-circuit exact lattice points, else compensated `r*ML_PI_HI_D + r*ML_PI_LO_D` then delegate to `ml_sin`/`ml_cos`.

## 2. The Algorithm (Execution Path)
*Trace the data flow from the raw `double` input to the final `double` output. What are the distinct phases?*
1. **Phase 1: Range Reduction / Pre-processing**
   - *Code location:* `ml_rem_pio2` in `src/internal/payne_hanek.h:174`, `ml_rem_pio2_large` in `src/internal/payne_hanek.h:103`, `ml_ph_process_term` in `src/internal/payne_hanek.h:57`.
   - *Why we do it:* raw x cannot go into a degree-19 polynomial; it must be mapped to y in -pi/4..pi/4 plus quadrant n 0..3. Small/medium path for `ml_fabs(x) <= 1.0e6` does 2-term Cody-Waite: `ml_round(x*ML_PH_TWO_OVER_PI)`, `ml_two_sum(x, -p)`, correction `r1_err - p_err - fn*ML_PH_PIO2_LO` with `ML_PH_PIO2_HI = 0x1.921fb54442d18p+0`, `ML_PH_PIO2_LO = 0x1.1a62633145c07p-54`. Large path for magnitude > 1e6 does Payne-Hanek V6 full-table sweep k=0..65 over `ml_two_over_pi` 24-bit chunks, splitting mantissa into `m_hi`/`m_lo`, per-term integer/fraction separation mod 4 with Kahan accumulation, centering frac to -0.5..0.5, reconstruct `ML_FMA(frac, ML_PH_PI2_HI, frac*ML_PH_PI2_LO)`. NaN/Inf gives NaN y. Embedded profile instead does `ml_fmod(x, 2.0*ML_PI)` in `ml_sin`/`ml_cos`/`ml_sincos_common`.
2. **Phase 2: The Core Approximation**
   - *Code location:* `ml_taylor_sin_raw` in `src/internal/minimax.h:24`, `ml_taylor_cos_raw` in `src/internal/minimax.h:54`, `ml_atan_raw_dd` in `src/trig.c:148`, `ml_cordic_sincos_fixed` in `src/fixed_point.c:89` for embedded.
   - *Why we do it:* on the reduced y the function is smooth and polynomial-friendly. Default path evaluates compensated double-double Horner in t=y*y as described in section 1. atan path evaluates 22-term double-double Horner after the pi/2/pi/4/pi/12 cascade. Embedded `MATHLIB_PROFILE_EMBEDDED` path skips polynomials: scales `r*65536.0` to `ml_q16_16_t f_in`, calls single `ml_cordic_sincos_fixed`, scales back `/65536.0`; 16-iteration Q16.16 CORDIC kernel with `fixed_cordic_atan` table and portable `ml_q16_asr`/`ml_i64_asr` shifts.
3. **Phase 3: Reconstruction / Post-processing**
   - *Code location:* `ml_minimax_sin` in `src/internal/minimax.h:65`, `ml_minimax_cos` in `src/internal/minimax.h:79`, `ml_sincos_common` in `src/trig.c:38`, `ml_atan` DD add-back in `src/trig.c:168-219`, `ml_tan` in `src/trig.c:75`, `ml_sec` in `src/trig.c:252`, `ml_csc` in `src/trig.c:265`, `ml_cot` in `src/trig.c:276`.
   - *Why we do it:* map reduced result back to original quadrant/domain. sin/cos swap by `n & 3`: n=0 s=sy c=cy, n=1 s=cy c=-sy, n=2 negate both, n=3 s=-cy c=sy. `ml_sincos_common` does this once and serves `ml_tan` (s/c), `ml_sec` (1/c), `ml_csc` (1/s), `ml_cot` (c/s) with ONE `ml_rem_pio2` call instead of two separate `ml_sin` plus `ml_cos` reductions. atan adds back pi/2, pi/4, pi/12 double-double slices. sinpi/cospi delegate compensated arg to `ml_sin`/`ml_cos` which re-reduce the small arg. Triangle helpers `ml_r_form`, `ml_triangle_area_sas`, `ml_law_cos_side`, `ml_law_sin_side`, `ml_polar_to_cart`, `ml_cart_to_polar`, `ml_heron`, `ml_stewart`, `ml_ceva` in `src/trig.c:352-522` layer on top of `ml_sin`/`ml_cos`/`ml_atan`/`ml_atan2`/`ml_sqrt`/`ml_hypot_internal` with their own scaling and guards.

## 3. The "Dark Arts" (Hardware & IEEE-754 Sympathy)
*Why did the AI write it this way instead of the naive textbook way?*
- **Exact-hex pi/12 double-double:** `ML_PI12_HI_D = 0x1.0c152382d7366p-2`, `ML_PI12_LO_D = -0x1.ee6913347c2a6p-56` in `src/trig.c:97-102`, with `ML_PI_HI_D = 0x1.921fb54442d18p+1`, `ML_PI_LO_D = 0x1.1a62633145c07p-53`. HI is correctly-rounded nearest double to true pi/12, LO is rounded remainder (negative because HI sits above true). Precomputing avoids double-rounding of `(PI_HI/12)+(PI_LO/12)` on every `ml_atan` call; comment in code states this explicitly. Slices pi/2 and pi/4 are exact halves/quarters of HI/LO, but pi/12 is not, hence the dedicated constants and the `ml_two_sum(c12h, a)` plus `e += c12l` pattern.
- **Cody-Waite vs Payne-Hanek split at 1e6:** threshold `ax <= 1.0e6` in `ml_rem_pio2`. Below it 2-term Cody-Waite with error-free transforms is < 1 ULP and fast. Above it the product `x*(2/pi)` has billions-scale integer part that swallows the fraction in double, so V6 restores per-term integer/fraction separation: `ml_ph_process_term` extracts integer mod 4 per term (shifts >= 2 contribute nothing, shift 1 gives `2*(prod mod 2)`, shift 0 gives `prod mod 4`, shift < 0 Kahan-accumulates fraction via `ml_ldexp_pure`). Full sweep k=0..65 guarantees no fractional bits dropped to ~1.8e308; V5 failed by accumulating the full product without mod-8 reduction.
- **Compensated r*HI+r*LO in sinpi/cospi:** `ml_sinpi`/`ml_cospi` compute `ahi = r*ML_PI_HI_D`, `alo = ML_FMA(r, ML_PI_HI_D, -ahi) + r*ML_PI_LO_D`, `arg = ahi+alo`. The `ML_FMA` recovers the rounding error of `r*HI` exactly (FMA is correctly rounded), then adds `r*LO`, giving ~106-bit pi*r without a full double-double multiply. Combined with exact `ml_fmod(x, 2.0)` reduction this keeps lattice points exact and small-r args correctly rounded-ish while large `x` still works via fmod.
- **Why Horner in double-double:** plain FMA Horner on degree-19 Taylor measured ~1-2 ULP evaluation noise; comment in `ml_taylor_sin_raw` notes compensated Horner brings evaluation under 0.3 ULP with truncation ~1e-22, so total < 1 ULP on -pi/4..pi/4. `ml_ddx_mul_d`/`ml_ddx_add_d` use `ml_two_sum` renorm per step, i.e. error-free transform per multiply-add, which is why the active Maclaurin kernels beat fitted Chebyshev under double Horner (see `docs/V12A1_MINIMAX_REPORT.md` exp table where noise grows with degree). atan needs it even more: 22-term sum to x^43 would lose the tail in double, so `ml_atan_raw_dd` keeps the accumulator as `ml_ddx_t` hi/lo pair.
- **Portability tricks:** `ml_cordic_sincos_fixed` avoids implementation-defined `>>` on negatives via `ml_i64_asr`/`ml_q16_asr` floor-division emulation; `ml_ceva` casts to `long double` BEFORE division so `1e-300/1e300`-style ratios do not over/underflow in double; `ml_sincos_common` single-reduction halves Payne-Hanek cost for tan/sec/csc/cot; `memcpy` for bit extraction in `ml_rem_pio2_large` avoids union aliasing issues.

## 4. Error Budget & Failure Modes
*Where does the physical limit of the silicon break the mathematical ideal?*
- **Maximum ULP Error vs mpmath 80-digit oracle, gate <= 5 ULP:** per `docs/PRECISION_CONTRACT.md` only `tests/test_oracle.c` plus `tests/oracle_data.h` (212 vectors, 7 families) certifies precision; smoke `ASSERT_NEAR 1e-9..1e-15` and edge suites prove nothing about ULP. Per `docs/V12A1_MINIMAX_REPORT.md` measured on reduced domains with FMA Horner: active kernels sin Maclaurin deg 19 = 1 ULP, cos Maclaurin deg 18 = 1 ULP, exp Taylor-19 = 1 ULP, log atanh 11-term = 1 ULP. Dormant `minimax_coeffs.h` fitted sets: sin deg 9 = 2 ULP, cos deg 8 = 5 ULP, exp Taylor-19 = 1 ULP, log deg 7 = 3 ULP. Hard gate: nothing ships unless every kernel <= 5 ULP; no swap happened because active already passes.
- **Small-arg Taylor truncation ~1e-20, < 1 ULP:** on -pi/4..pi/4 the degree-19/18 tails are ~1e-22..1e-20, below half-ULP at magnitude ~1 (2.2e-16), so error is evaluation-dominated and compensated Horner keeps it < 1 ULP. atan core after reduction to magnitude <= 0.2679 has truncation far below double epsilon; measured < 0.001 ULP for the raw polynomial, total atan error dominated by the DD pi-slice add-back rounding (~0.5-1 ULP).
- **Large-arg Payne-Hanek ~1e-14 rad, hundreds of ULP:** for magnitude > 1e6 the reduced-arg absolute error grows to ~1e-14 rad because only 66x24-bit = 1584 bits of 2/pi are tabulated and the 53-bit mantissa split plus Kahan accumulation cannot preserve full precision to 1e308. Phase error then amplifies by 1 near sin/cos zeros, i.e. hundreds of ULP in output. Oracle therefore only checks finiteness plus s-squared plus c-squared equals 1 there, not absolute ULP.
- **Embedded CORDIC ~1e-3 rad, edge tolerance only:** `MATHLIB_PROFILE_EMBEDDED` Q16.16 16-iteration path with corrected `fixed_cordic_atan` table still carries ~2 LSB residual angle error plus 1/65536 quantization, observed ~1e-3 rad. `ml_sin`/`ml_cos`/`ml_sincos_common` embedded branches are covered by edge directed suites with loose tolerance, never by the <= 5 ULP oracle gate.
- **Catastrophic Cancellation:** the code routes around it explicitly: `ml_asin` switches to `pi/2 - 2*ml_atan(ml_sqrt((1-x)/(1+x)))` for x > 0.9 where `1-x*x` cancels; `ml_acos` mirrors it; `ml_acot` uses `ml_atan(1/x)` for magnitude > 1 instead of `pi/2-ml_atan(x)` where `ml_atan(x)` near pi/2 loses relative accuracy; Cody-Waite uses `ml_two_sum` so `x-p` does not lose the tail; sinpi uses compensated `r*HI+r*LO` so `r*HI` rounding does not eat `r*LO`.
- **Overflow/Underflow Boundaries:** trig outputs never overflow to Inf from finite inputs; magnitude <= 1 for sin/cos/sinpi/cospi, atan bounded by pi/2. `ml_heron` returns `ml_make_inf(0)` only when finite sides have true area overflow via stable sorted product `(x+(y+z))*(z-(x-y))*(z+(x-y))*(x+(y-z))`; `ml_law_cos_side` scales by `max(ml_fabs(a),ml_fabs(b),1)` and `ml_stewart` by `max(magnitudes,1)` so `a*a+b*b` cannot overflow. Subnormals pass through polynomial paths without flush-to-zero; `ml_sinc` small-arg branch and `ml_sinpi` signed-zero returns preserve them.
- **NaN Propagation:** `ml_sin`/`ml_cos`/`ml_sinpi`/`ml_cospi` return `ml_make_nan()` on NaN/Inf; `ml_rem_pio2` returns NaN y on NaN/Inf and callers propagate; `ml_asin`/`ml_acos` return NaN outside -1..1; `ml_atan` passes NaN through, maps plus/minus Inf to plus/minus pi/2 via `ml_copysign`; `ml_atan2` returns NaN if either arg NaN; `ml_acot` passes NaN, maps plus/minus Inf to 0/pi; `ml_sinc` passes NaN, maps Inf to 0.0; triangle helpers `ml_r_form`/`ml_triangle_area_sas`/`ml_law_cos_side`/`ml_law_sin_side`/`ml_polar_to_cart`/`ml_cart_to_polar`/`ml_heron`/`ml_stewart` return NaN on NaN/Inf/negative-side inputs, `ml_ceva` returns 0 on NaN/Inf/zero-divisor.
- **Pole behavior tan/sec/csc/cot, 1/c blow-up never exactly 0:** `ml_tan`/`ml_sec`/`ml_csc`/`ml_cot` share one `ml_sincos_common` reduction. If denominator is exactly 0.0 they return IEEE `s/c`, `1/c`, `1/s`, `c/s` so signed zeros give correctly-signed Inf; only 0/0 (both zero from rounding failure) returns NaN. In practice the reduced `ml_taylor_cos_raw`/`ml_taylor_sin_raw` never return exactly 0.0 at pi/2 or pi multiples except exact lattice points, so poles manifest as large finite values ~1e16 rather than Inf; there is no epsilon snap-to-Inf.
